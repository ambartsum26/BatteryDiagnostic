# DevicePulse 0.9.14 — совместимость датчиков

Новая отдельная сборка на основе последней успешной сборки исходников 0.9.11 (704ef16aa34995bb8608a1e10a2fe6ee7f79c4e9). Эталонный EXE 0.9.13 не изменён: соответствующих исходников в репозитории нет. Эта сборка не объявляется заменой эталона до проверки на реальных ПК.

## Использование

Распакуйте весь ZIP. Запустите DevicePulse.exe. Оставьте папку smartmontools и файл libcdi.dll рядом с приложением. Командная строка не нужна. Windows запросит права администратора. Существующее французское окно установки официального подписанного PawnIO 2.2.0 сохранено. Для CPU драйвер может потребоваться; его установка в CI не выполняется.

## Источники

- CrystalDiskInfo через libcdi из официального NWinfo v1.6.6. Сохранены проверка SHA-256, исходные лицензии и привязка к физическому диску.
- smartmontools 7.5: отдельный read-only процесс smartctl; полная совместимая база drivedb/7.5, commit 764fcfb2472920fcaeb62950e60cb8bf3f983065. Новые профили производителей применяет сама библиотека smartmontools. База охватывает ATA/SATA SSD, HDD и USB-мосты в пределах её опубликованной поддержки. NVMe и SAS/SCSI читаются через поддерживаемые протоколы. Программа не запускает тесты поверхности, smartd или изменение настроек диска.
- LibreHardwareMonitorLib 0.9.6: Intel и доступные реализации AMD (семейства 0Fh, 17h, 19h, 1Ah). Старые семейства 10h–16h отключены в этой версии самой библиотеки. Прямой Intel DTS сохраняет отдельную проверку модели и аппаратного TjMax.
- AIDA64 и HWiNFO: сохранено чтение CPU из документированной общей памяти, когда соответствующая программа запущена и публикация включена. В AIDA64: Preferences → Hardware Monitoring → External Applications → Enable shared memory. Движок и коммерческие базы AIDA64 не включены в приложение.
- RAM: SMBIOS Type 17, резерв Win32_PhysicalMemory с точной привязкой по слоту и объёму. DDR3/DDR4/DDR5 и LPDDR распознаются по коду прошивки, не по частоте. Бренд модуля не выдаётся за производителя чипов. Датчик температуры RAM присутствует не у всех модулей и этой доработкой не обещается.

## Защита достоверности

Нет универсального процента здоровья HDD. Для SSD процент обозначает остаток ресурса, а не вероятность отказа. Отсутствующие данные остаются недоступными. Противоречивые оценки ресурса не превращаются в 100%. Предупреждения SMART, ошибки NVMe и критические пороги важнее процента. Новое чтение запускается с ограничением времени и размера ответа; бинарный файл и база проверяются по SHA-256. Номер физического диска и модель должны совпасть. Серийные номера не выводятся новым провайдером.

## Проверки

Сборка должна пройти новые синтетические проверки SMART/CPU/RAM, существующие проверки батареи, интерфейса и локализации FR/EN/RU. CI выполняет smartctl --version, но не обращается к физическим дискам и не устанавливает драйвер. Итоговый EXE публикуется отдельно с requireAdministrator; его манифест проверяется без запуска. Результаты конкретного запуска находятся в GitHub Actions.

Физические датчики Intel/AMD, контроллеры Intel RST/RAID и USB-корпуса требуют проверки на настоящем оборудовании. Полную совместимость со всеми существующими накопителями и CPU гарантировать нельзя.

## Лицензии и исходники

smartctl работает отдельным процессом. В папке smartmontools находятся его GPL COPYING, исходный архив smartmontools-7.5-source.tar.gz и точный использованный drivedb.h. Исходник drivedb.h: https://github.com/smartmontools/smartmontools/blob/764fcfb2472920fcaeb62950e60cb8bf3f983065/smartmontools/drivedb.h . Остальные лицензии сохранены в ThirdPartyNotices.txt и libcdi-LICENSE.txt.

Полные исходники DevicePulse публикуются отдельным артефактом. Сборка: .NET 10 SDK, dotnet publish src/BatteryDiagnostic.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true. Пакеты и версия проверяемых внешних компонентов зафиксированы в проекте и workflow. Для обычного запуска сборка исходников не требуется.
